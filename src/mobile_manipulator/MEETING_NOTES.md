# 주간 미팅 자료 — URDF 직접 제작 (OMX 분석 → SCARA → 6축)

> 슬라이드 7장, 발표 5분 기준. 각 장 = 제목 / 핵심 메시지 / 본문(표·불릿) / 발표 멘트.
> 모든 수치는 2026-09-28 실측 또는 URDF에서 계산한 값 (ROS 2 Humble, Gazebo Classic 11).

## 1. 이번 주 목표와 진행 흐름

**핵심 메시지** — OpenManipulator-X(OMX) URDF를 분석한 뒤, 같은 방식으로 SCARA와 6축 로봇의 URDF를 직접 만들어 시뮬레이션에서 구동함.

**진행 흐름**
OMX URDF 분석 → SCARA 모바일 매니퓰레이터 제작 → UR식 6축 모바일 매니퓰레이터 제작 → 3종 비교

**결과 요약**
- 두 로봇 모두 RViz 시각화, Gazebo 시뮬레이션, ros2_control 구동(주행·팔·그리퍼)까지 완료
- 역기구학 직접 구현: SCARA는 닫힌해(코사인 법칙), 6축은 수치해(야코비안)
- 두 방식의 성공률·속도·한계를 실측으로 비교

**발표 멘트** — "OMX 구조를 먼저 뜯어보고, 그 구조를 그대로 따라 SCARA와 6축을 직접 만들어 비교했습니다."

## 2. OpenManipulator-X URDF 구조 분석

**핵심 메시지** — OMX는 기능별로 xacro 파일을 나누고, 실제 하드웨어 구동에 맞춰 설계되어 있음.

**파일 구성** (`open_manipulator_x_description`, 6개 파일 639줄)

| 파일 | 역할 |
|---|---|
| `open_manipulator_x_robot.urdf.xacro` | 최상위. 아래 파일 include, world 고정 joint, 인자(use_sim, use_fake_hardware, port_name) |
| `open_manipulator_x.urdf.xacro` | 링크·관절 정의 매크로 (265줄) |
| `gazebo/*.gazebo.xacro` | 링크 마찰·색상, transmission |
| `ros2_control/*.ros2_control.xacro` | 하드웨어 인터페이스 (196줄) |

**관절 구성** — 4자유도 + 그리퍼

| 관절 | 종류 | 축 | 범위 |
|---|---|---|---|
| joint1 | revolute | z | ±π |
| joint2 / joint3 / joint4 | revolute | y | ±1.5 / −1.5~1.4 / −1.7~1.97 |
| gripper_left_joint | prismatic | y | −0.010~0.019 m |
| gripper_right_joint | prismatic (mimic) | −y | left를 따라감 |

**특징**
- 형상: CAD STL 메시 사용 (`scale="0.001"`로 mm → m 변환)
- 관성: CAD에서 뽑은 실측값 (질량 합 0.594 kg)
- 하드웨어 3모드: Gazebo / Fake / 실제 Dynamixel. 실제 모드에는 관절↔모터 변환행렬, 회전 모터로 직선 그리퍼를 구동하는 변환 파라미터가 있음
- mimic 관절 처리를 위한 더미 링크(`dummy_mimic_fix`), ROS 1 방식의 transmission 태그가 남아 있음
- 도달 거리(계산값): joint1 축에서 수평 0.38 m

**발표 멘트** — "OMX는 파일을 역할별로 나눠 두었고, 같은 URDF로 시뮬레이션과 실제 로봇을 모두 돌릴 수 있게 되어 있습니다. 이 구조를 그대로 따라 만들었습니다."

## 3. SCARA 모바일 매니퓰레이터 설계

**핵심 메시지** — 차동구동 베이스 위에 SCARA 팔(R-R-P-R)을 올리고, CAD 없이 기본 도형과 관성 공식만으로 모델링함.

**관절 구성**

| 관절 | 종류 | 축 | 범위 | 컨트롤러 |
|---|---|---|---|---|
| 좌/우 바퀴 | continuous | y | 무한 | diff_drive_controller |
| joint1 어깨 / joint2 팔꿈치 | revolute | z | ±2.5 rad | arm_controller |
| joint3 수직축(quill) | prismatic | −z | 0~0.18 m | arm_controller |
| joint4 손목 | revolute | z | ±π | arm_controller |
| 그리퍼 좌/우 | prismatic (mimic) | ±y | 0~0.03 m | gripper_controller |

**설계 결정**
1. **기본 도형 + 관성 공식**: box / cylinder / sphere 관성 공식을 xacro 매크로로 만들어 모든 링크에 적용 (관성값이 0이면 Gazebo가 불안정해짐)
2. **기둥 높이 0.25 m**: 0.20 m로 두면 팔이 베이스 위를 지날 때 손끝(지면 위 0.15 m)이 베이스 윗면(0.15 m)과 부딪히는 것을 계산으로 확인하고 수정
3. **수직축을 −z 방향 prismatic으로**: 명령값이 양수이면 내려가도록 해서 IK 식을 단순화 (q3 = 0.20 − z)

**역기구학 (닫힌해)**
q2 = ±acos((x² + y² − L1² − L2²) / 2L1L2),  q1 = atan2(y, x) − atan2(L2 sin q2, L1 + L2 cos q2),  q4 = yaw − q1 − q2

## 4. OMX vs SCARA 비교

**핵심 메시지** — 파일 구조는 OMX를 따르되, 모델링 방식과 로봇 구성은 목적에 맞게 바꿈.

| 항목 | OpenManipulator-X | SCARA (직접 제작) |
|---|---|---|
| 형상 | CAD STL 메시 | box / cylinder / sphere |
| 관성 | CAD 실측값 | 균일 밀도 공식 매크로 |
| 베이스 | world에 고정 | 차동구동 모바일 베이스 (6.1 kg) |
| 자유도 | 4 (R-R-R-R) + 그리퍼 | 4 (R-R-P-R) + 그리퍼 + 바퀴 2 |
| 생성 URDF | 링크 10 / 관절 9 | 링크 13 / 관절 12 |
| 팔 질량 | 0.594 kg | 1.19 kg (기둥 0.5 kg 포함) |
| 수평 도달 거리 | 0.38 m | 0.35 m |
| 치수 관리 | 각 관절 origin에 숫자 직접 입력 | `common.xacro`에 property로 모아 한 곳에서 수정 |
| 하드웨어 모드 | Gazebo / Fake / Dynamixel | Gazebo / Mock |
| 역기구학 | MoveIt (KDL 수치해) | 닫힌해 직접 구현 |
| xacro 코드 | 6개 파일 639줄 | 6개 파일 505줄 |

**발표 멘트** — "SCARA는 회전축이 모두 수직이라 중력이 수직축 하나에만 걸리고, 역기구학이 평면 2링크 문제로 단순해집니다."

## 5. UR식 6축 모바일 매니퓰레이터 설계

**핵심 메시지** — 같은 베이스에 UR식 6축 팔을 올리되, SCARA 파일은 수정하지 않고 include로만 재사용함.

**관절 구성** (0 자세 = 팔이 위로 곧게 선 자세, UR처럼 어깨·팔꿈치·손목에 옆 방향 오프셋)

| 관절 | 축 | 부모 기준 위치 (m) | 범위 (rad) |
|---|---|---|---|
| joint1 shoulder_pan | z | (0, 0, 0.10) | ±π |
| joint2 shoulder_lift | y | (0, 0.07, 0) | ±2.0 |
| joint3 elbow | y | (0, −0.06, 0.22) | ±2.6 |
| joint4 wrist1 | y | (0, 0, 0.20) | ±π |
| joint5 wrist2 | z | (0, 0.05, 0) | ±π |
| joint6 wrist3 | y | (0, 0, 0.05) | ±π |

**파일 재사용 구조**
- 새 파일 4개(349줄): 최상위, 팔+그리퍼, ros2_control, gazebo
- 기존 파일 include: `common.xacro`(치수·관성 공식), `base.xacro`(베이스), `ros2_control.xacro`·`gazebo.xacro`(공용 매크로 정의만)
- 컨트롤러·액션 이름을 SCARA와 같게 맞춰, 제어 명령 구조가 동일함

**역기구학 (수치해, damped least squares)**
- URDF에서 관절 체인을 직접 읽어 순기구학 계산 (치수 하드코딩 없음)
- 기하 야코비안: 회전관절 i의 열 = [ zᵢ × (p_e − pᵢ) ; zᵢ ]
- 반복: Δq = Jᵀ(JJᵀ + λ²I)⁻¹ e,  e = [위치 오차 ; 자세 오차(축각)],  λ = 0.05
- 종료 조건: 위치 0.1 mm, 자세 0.001 rad 이내
- 곧게 선 0 자세는 특이점이라, 준비 자세로 옮긴 뒤 IK를 풂

## 6. 3종 종합 비교

**핵심 메시지** — 자유도가 늘어나면 작업 공간과 자세 자유도는 커지지만, 역기구학은 닫힌해에서 수치해로 바뀌어 느려지고 실패 가능성이 생김.

| 항목 | OMX | SCARA | UR식 6축 |
|---|---|---|---|
| 팔 자유도 | 4 | 4 | 6 |
| 관절 구성 | R-R-R-R | R-R-P-R | R-R-R-R-R-R |
| 제어 가능한 끝점 자유도 | 위치 3 + pitch | 위치 3 + yaw | 위치 3 + 자세 3 |
| 생성 URDF (링크 / 관절) | 10 / 9 | 13 / 12 | 17 / 16 |
| 팔 질량 | 0.594 kg | 1.19 kg | 1.94 kg |
| 수평 도달 거리 (계산값) | 0.38 m | 0.35 m | 0.54 m |
| 손끝 높이 범위 (계산값) | −0.18 ~ 0.46 m | 0.02 ~ 0.20 m | −0.16 ~ 0.79 m (0 아래는 지면에 막힘) |
| 중력이 걸리는 관절 | joint2·3·4 | joint3 (수직축) 하나 | joint2·3·4 |
| 역기구학 | MoveIt | 닫힌해 | 수치해 (야코비안) |
| 새로 작성한 xacro | - | 505줄 | 349줄 (+ 기존 파일 재사용) |

**역기구학 성능 실측** (무작위 목표, Python, 같은 PC)

| 항목 | SCARA 닫힌해 | 6축 수치해 |
|---|---|---|
| 테스트 목표 | 도달 가능한 무작위 1000개 | 작업 목표 200개 (앞쪽, 그리퍼 아래 방향) / 도달 가능한 무작위 자세 200개 |
| 성공률 (초기값 1개) | 100% | 83.5% / 54.0% |
| 성공률 (초기값 10개 추가 재시도) | - | 93.5% / 94.0% (별도 샘플 200개) |
| 평균 반복 횟수 | 1회 (공식) | 13.3회 / 43.6회 |
| 1회 계산 시간 | 3.5 µs | 5.2 ms / 16.8 ms (약 1500~5000배) |
| 최대 오차 | 0 mm | 위치 0.1 mm, 자세 0.02° 이하 |

**발표 멘트** — "6축은 끝점 자세까지 맞출 수 있지만, 수치해라서 초기값에 따라 국소해에 빠집니다. 도달 가능한 목표인데도 초기값 하나로는 절반 정도만 풀렸고, 초기값을 바꿔 다시 시도하면 94%까지 올라갔습니다."

## 7. 시뮬레이션 검증 결과 · 겪은 문제 · 다음 계획

**Gazebo 실측**

| 항목 | SCARA | UR식 6축 |
|---|---|---|
| 컨트롤러 4개 (상태 / 주행 / 팔 / 그리퍼) | 모두 active | 모두 active |
| 스폰 후 기울기 (roll, pitch) | 약 0 rad (1e−4 이하) | 약 0 rad (1e−4 이하) |
| 주행: 0.2 m/s로 약 4초 | 실제 0.698 m, 오도메트리 0.697 m | 데모 중 정상 주행, 넘어짐 없음 |
| IK 목표 대비 실제 손끝 (TF) | (0.30, 0.15, 0.03) → 오차 0 mm | (0.40, 0, 0.20) → 오차 0 mm, 자세 오차 0 |
| 데모 | 전 과정 성공 | 목표 4개 중 3개 성공, 4번째 실패 (아래) |

**겪은 문제와 해결**
1. **Gazebo 컨트롤러가 뜨지 않음** — xacro 주석의 "1축: 어깨"처럼 콜론+공백이 있으면 파싱 에러 발생. gazebo_ros2_control이 URDF 전체를 YAML 파라미터로 넘기기 때문. 주석에서 콜론을 빼서 해결
2. **첫 실행 시 로봇 스폰 실패** — Gazebo 기동이 기본 대기 시간 30초를 넘김. 대기 시간을 120초로 늘려 해결
3. **6축 IK 국소해 (미해결)** — 목표 (0.30, −0.25, 0.20, yaw 90°)에서 수렴 실패. 해는 존재하지만(joint6 = +2.19), 현재 값 −1.74에서 출발하면 joint6의 ±π 한계에 막혀 반대 방향으로 넘어가지 못함. 초기값을 무작위로 바꿔 재시도하면 풀리는 것을 확인

**다음 계획**
- 6축 IK에 무작위 재시작 추가, 관절 한계를 고려한 방식(null-space 등) 검토
- MoveIt 연동해서 충돌 회피 경로 계획과 비교
- Gazebo에서 실제 물체 집기 테스트
